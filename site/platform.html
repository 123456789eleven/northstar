Platform

How Northstar is built.

A small number of ideas, applied consistently: one data store, one set of objects, and workflows that act on them.

Every module reads and writes the same linked objects, so a task can advance a goal and a transaction can be traced to a person or a meal.

Data

Your entries, CSV files you choose to import, and JSON backups. By default all of it is stored in IndexedDB in your own browser, and only there. Every table is declared in one schema, and upgrades are versioned so existing data survives.

Models

Deterministic rules you can read: overdue detection, budget pace, contact cadence. Opt-in AI is a possible later addition and would never be on by default or send data without your explicit approval.

Ontology

Seven object types (Task, Goal, Person, Transaction, Meal, Course, Event) with typed links. Each object has properties, functions that compute from it, actions you can take, and automations that fire as a result.

Workflows

Quick capture turns one line of text into the right object. The Weekly Review summarizes the week and sets the next. The Planner, Habits and Journal read and write the same store. Each aims at one or two taps for the common case.

Analytics

Insights are charts and summaries drawn from the same objects, so a number on a chart can be traced to the entries behind it.

Integrations

Deliberately narrow and all opt-in. Bank data comes in only as a CSV you pick yourself, with no bank logins. Backups go out only as a file you save. The Data Hub can connect your Google Calendar read-only; that starts only when you press Connect, and nothing you stored is sent to Google. Food search can query Open Food Facts, only when you turn it on, and sends just the text you search for. Optional sync copies end-to-end encrypted records to your own Supabase project.

The timeline

Whenever something meaningful happens, such as a task done or a course finished, one event is written. History and the milestones wall read only from that timeline.
