Security

How encrypted sync keeps your data unreadable to the server.

You only need this page if you turn sync on. Without sync, your data never leaves your device.

The idea in one paragraph

When you turn on sync, your device locks every record in a box before sending it, and only you have the key. The server stores locked boxes. It can count them and see when they changed, but it cannot open them. Your passphrase is what unlocks your key, and your passphrase never leaves your devices.

Step by step

  1. You choose a passphrase. Northstar stretches it into a key with PBKDF2-SHA256 using 600,000 rounds. The deliberate slowness makes guessing passphrases expensive.
  2. A data key protects your records. A random data key does the real encryption. It is stored, wrapped (encrypted) by your passphrase-derived key, and also wrapped by a one-time recovery code you are shown once.
  3. Each record is encrypted separately. Every task, entry or transaction becomes its own ciphertext using AES-256-GCM, with a fresh random value each time. GCM also detects tampering: a modified box fails to open.
  4. Each box is bound to its place. The table name and record id are mixed in as authenticated data, so a record cannot be swapped into a different slot unnoticed.
  5. Only ciphertext is uploaded. Other devices download the boxes and open them with the same key, which they get by entering your passphrase.

What the server can and cannot see

The server can seeThe server cannot see
Your account email and sign-in timesThe text, amounts, dates or names inside any record
Which tables exist and how many records each hasYour passphrase, recovery code or encryption keys
When records were created, changed or deletedWhich task, goal, transaction or journal entry a box is
The size of each encrypted recordAnything in device-only settings, which never sync

Sizes and counts are a real leak of metadata: a very long journal entry makes a bigger box. If that matters to you, keep sync off.

Who holds which key

  • Your passphrase and recovery code live in your head or your password manager. Northstar cannot recover them.
  • Row-level security in your Supabase project means your signed-in account can only read and write its own rows. The app never contains a service-role key.
  • Conflicts are resolved by the newest change, using a timestamp inside the ciphertext, so the server cannot reorder your edits.

Lose both and the cloud copy is gone. If you lose your passphrase and your recovery code, nobody can decrypt the cloud copy, including you, Supabase and Northstar. The readable copy on each device is unaffected, so export a backup.

What this does not protect against

  • Someone with access to your unlocked device or browser profile, since the local database is readable by the app. Use your device’s screen lock and disk encryption.
  • Malware on your device, or a weak passphrase. Choose a long one.
  • Backup files you export: they are plain JSON. Store them carefully.

The exact network paths for every opt-in feature are on the Privacy page. Setup instructions for sync are in the repository under supabase/README.md.
